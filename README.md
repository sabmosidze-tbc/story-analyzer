# StoryAnalyzer

A QA-focused web app. It loads Jira stories, analyzes them with AI, and produces scenarios, test cases and checklists you can export to Jira, Excel or PDF. It also helps you report bugs straight into Jira.

---

## 1. Setup

You need 7 values in a file called `.env.local`. This section explains what each one is, why it's needed and exactly how to get it.

### Requirements
- Node.js 20+ and npm
- A Jira Cloud account
- A GitHub account with an active **GitHub Copilot** subscription (the AI runs on it)

### Install

```bash
npm install
```

### Overview of the 7 values

| Key | What it is | Why it's needed | Where it comes from |
|---|---|---|---|
| `JIRA_BASE_URL` | Your company's Jira address | Tells the app which Jira to talk to | Your browser's address bar |
| `JIRA_EMAIL` | The email you log in to Jira with | Atlassian tokens only work together with the email of the account that made them. Also decides whose name appears on bugs and comments | You already know it |
| `JIRA_API_TOKEN` | Your password for the app | Lets the app load stories and create/edit bugs and comments as you | Atlassian, created by you (step A) |
| `AUTH_GITHUB_ID` | The OAuth app's Client ID | GitHub requires every app that offers "Sign in with GitHub" to be registered. This says which app is asking | GitHub, after registering an OAuth App (step B) |
| `AUTH_GITHUB_SECRET` | The OAuth app's Client secret | The registered app's password, proving it's really your app | GitHub (step B) |
| `AUTH_SECRET` | A random string you make up | Locks the login cookie, which holds your GitHub token. The login library refuses to run without it | Generated by you (step C) |
| `AUTH_URL` | The app's own address | Used to build the return link GitHub sends you back to after login | Type `http://localhost:3000` |

You do **not** need a GitHub personal access token (`GITHUB_TOKEN`). The old "GitHub Models" token was retired on July 30, 2026, and the app ignores it. When you sign in, GitHub gives the app a token for you automatically, and the app uses it to call Copilot with your own subscription.

### Step A. Jira values

1. `JIRA_BASE_URL`: open Jira in your browser and copy the address up to `.atlassian.net`, for example `https://yourcompany.atlassian.net`. No `/` at the end.
2. `JIRA_EMAIL`: the email you use to log in to Jira.
3. `JIRA_API_TOKEN`:
   1. Open <https://id.atlassian.com/manage-profile/security/api-tokens>
   2. Click **Create API token**, give it a name (e.g. `StoryAnalyzer`) and click **Create**.
   3. Copy the token immediately. Atlassian shows it only once.

### Step B. Register a GitHub OAuth App (`AUTH_GITHUB_ID` and `AUTH_GITHUB_SECRET`)

1. Open <https://github.com/settings/developers> and click **OAuth Apps** (not "GitHub Apps"), then **New OAuth App**.
2. Fill in the form:
   - **Application name:** `StoryAnalyzer`
   - **Homepage URL:** `http://localhost:3000`
   - **Redirect URI** (older GitHub forms call it "Authorization callback URL"): `http://localhost:3000/api/auth/callback/github`. This is the page GitHub sends you back to after you click Allow. GitHub only sends logins to addresses registered here, so it must match exactly or you'll see a "redirect_uri mismatch" error.
   - **Allow wildcard matching:** leave unchecked.
   - **Enable Device Flow:** leave unchecked.
   - **Expire user access tokens:** **uncheck** it. The app doesn't handle refresh tokens, so an expiring token could break the AI mid-session.
3. Click **Register application**.
4. Copy the **Client ID** into `AUTH_GITHUB_ID`.
5. Click **Generate a new client secret** and copy it into `AUTH_GITHUB_SECRET`. GitHub shows it only once. If you lose it, generate a new one.

### Step C. Generate `AUTH_SECRET`

Any long random text works. It's made up by you, once, and isn't tied to GitHub or Jira. Easiest way (needs only Node):

```bash
node -p "require('crypto').randomBytes(32).toString('base64')"
```

Paste the output after `AUTH_SECRET=`. Don't change it later, or everyone is signed out once. (`openssl rand -base64 32` does the same on macOS/Linux; Windows doesn't have `openssl` by default.)

### Step D. Create `.env.local`

Create `.env.local` in the project root. **Never commit it.** One `NAME=value` per line, with no quotes and no spaces around `=`:

```env
JIRA_BASE_URL=https://yourcompany.atlassian.net
JIRA_EMAIL=you@company.com
JIRA_API_TOKEN=paste-the-atlassian-token

AUTH_GITHUB_ID=paste-the-client-id
AUTH_GITHUB_SECRET=paste-the-client-secret
AUTH_SECRET=paste-the-random-string
AUTH_URL=http://localhost:3000
```

Optional:

```env
COPILOT_MODEL=claude-sonnet-5.5   # default Copilot model
OPENAI_API_KEY=                   # alternative AI provider
ANTHROPIC_API_KEY=                # alternative AI provider
```

### Step E. Run

```bash
npm run dev
```

Open <http://localhost:3000>, click **Sign in with GitHub** and press **Authorize**. Restart `npm run dev` any time you change `.env.local`.

For a production build: `npm run build && npm start`. Then set the same variables on your host and change the Homepage URL and Redirect URI of the OAuth app to your real domain.

### Notes on login
- Each person who runs the app on their own computer needs their own `.env.local` with their own Jira token. The GitHub OAuth app (ID and secret) can be shared privately or each person can register their own.
- Every user's AI runs on **their own** Copilot subscription.
- A sign-in lasts **8 hours**, then you're sent back to the login page.
- Bugs and comments appear under the Jira account in `JIRA_EMAIL`.

### Troubleshooting

| Problem | Fix |
|---|---|
| "AI provider returned an empty response" | Sign in with GitHub and choose a Copilot model. Check that your account has Copilot. |
| `redirect_uri mismatch` on login | The Redirect URI in the GitHub OAuth app must be exactly `http://localhost:3000/api/auth/callback/github`. |
| Login errors about a missing secret | `AUTH_SECRET` is empty or missing in `.env.local`. Restart after adding it. |
| Jira calls fail with 401/403 | Check `JIRA_EMAIL` and `JIRA_API_TOKEN`. The token may have been mistyped or revoked. |
| Changes to `.env.local` have no effect | Restart `npm run dev`. |
| Big uploads fail | Uploads are limited to 250 MB (`next.config.ts`). |

## 2. What the app does

### Story Analyzer
Paste a Jira key or URL (or raw text). The app loads the story and runs the analysis. Keys that are Bugs or Epics are rejected here with a clear message, since those have their own flows.

Results appear in tabs:
- **Explanation** – plain-English summary, business purpose, user flow, technical notes. Long text scrolls inside the card.
- **Scenarios** – test design scenarios with coverage, as bordered cards with Preconditions, Steps and Expected result.
- **Test Cases** – grouped test suggestions with a structured editor (what to check, input, expected).
- **Ambiguities / Assumptions / Open Questions** – extracted from the story. Tabs with no items are hidden.

Every section can be edited and posted to Jira as a comment.

### Update from Jira
If the ticket changed in Jira, **Update from Jira** compares the text. If nothing changed it says so. If it changed, it asks you to confirm before re-analyzing, so your current analysis is never replaced by accident.

### Checklist
Environment-based checklists for a story. Your list of environments (e.g. D02, Q01) is editable, saved in your browser, and shared with the bug form.

### Epic Analyzer
Select an epic to see its stories as cards and analyze the whole epic: context, how stories relate, and gaps. Epics can be opened and closed.

### Report a bug
Create a well-structured Jira Bug from inside the app:
- Multiple problems per card, each with steps, requests, expected and actual results.
- Screenshots and videos per section (paste, pick or drag in).
- Priority, components, **labels** (loaded from Jira only when you click the field) and environment.
- Links the bug to the story. The description uses a clean Jira layout with green Expected and red Actual panels.

### Bugs I reported
A personal list with live Jira status, search and scrolling.
- **Edit** (pencil) – change a bug and save back to Jira.
- **Update from Jira** (refresh icon) – pull the latest title and text if someone changed the ticket.
- **Load by key** – open any existing ticket (not Epics) to edit it, even if it became a Task or was reformatted.
- Items show **Not in Jira** if the ticket was deleted. Removing an item from the list never deletes anything in Jira. Entries older than 30 days are dropped from the list.
- Edit-save is only enabled when something changed.

### Observations
Log non-bug findings and track their state (open → fixed → retest passed/failed). Each state change posts a comment on the Jira ticket.

### API requests
Capture request details and attach them to bug reports.

### Exports
Export results to Excel (including Zephyr-style test cycles), PDF, and Jira comments.

### History & settings
All analyses are saved in your browser (`localStorage`). Rename, reopen or delete them from the sidebar. Dark mode follows your system.

## 3. Notes
- Data lives in the browser; nothing is stored on a server database.
- The app writes to Jira (bugs, comments, edits) as the configured Jira user. Use a test project first if unsure.
- This project uses Next.js 16, which has breaking changes from older versions. See `node_modules/next/dist/docs/` before changing framework-level code.
